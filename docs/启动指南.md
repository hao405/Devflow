# DevFlow AI v1.0.0 启动指南

## 本地运行

需要 Python 3.12+、Node.js 20+ 和 Docker Compose。以下步骤从项目根目录开始。

1. 复制 `.env.example` 为 `.env`，按实际服务填写凭证；不要提交 `.env`。在本地评估环境中启动，按需设置 `TOKEN_ENCRYPTION_KEY`。
2. 执行 `docker compose up -d postgres etcd minio milvus`，启动关系数据库与向量检索基础设施。
3. 创建后端虚拟环境并安装依赖：

```bash
cd backend
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
# 默认 qwen_local Embedding 还需要以下可选依赖及首次模型下载：
pip install -r requirements-local-embedding.txt
uvicorn app.main:app --reload
```

Windows PowerShell 使用 `.venv\Scripts\Activate.ps1` 激活虚拟环境。

另开终端启动前端：

```bash
cd frontend
npm ci
npm run dev
```

前端地址为 `http://localhost:3000`，后端健康检查为 `http://localhost:8000/health`，API 文档为 `http://localhost:8000/docs`。

在后端目录通过 `PYTHONPATH=.` 运行脚本，例如 `PYTHONPATH=. python ../scripts/seed_demo_data.py`。种子脚本会写入演示数据并索引文档，应在本地演示数据库和所需检索服务可用后执行。

## 模型与检索配置

- 模型服务配置使用 `LLM_API_KEY`、`LLM_BASE_URL`、`LLM_MODEL`。
- 默认使用本地 Qwen Embedding，需要安装可选依赖并下载模型；也可按配置中的 provider 使用 API Embedding。
- Windows 的 `scripts/start_rag.ps1` 提供 SQLite 与 deterministic embedding 演示。该模式禁用 Milvus，向量检索显示 degraded，只支持演示范围内的验证。
- 固定回归评测集应放在 `docs/datas/evals/`，并导入其引用的知识文档。当前发布包不包含该基准数据；自动文档冒烟测试不能替代正式基线。

## 可选 Linux Docker 部署

`docker-compose.deploy.yml` 使用 Linux 主机网络，服务监听回环地址。填好 `.env` 后，在 Linux 主机上执行：

```bash
docker compose -f docker-compose.yml -f docker-compose.deploy.yml up -d --build
```

前端访问端口为 3000，后端为 8000。远程访问需自行配置端口转发或反向代理，并使 `NEXT_PUBLIC_API_BASE_URL` 与浏览器能访问的后端地址一致。首次构建涉及 Python、Node、PyTorch、Go 依赖及模型下载。
