# Agent Eval 不能只看回答像不像（核心精简版）

Agent Eval（智能体评测）需要同时检查结果和执行过程。回答即使读起来合理，也可能没有找到正确证据、遗漏必需工具，或在工具失败后继续给出结论。DevFlow-AI 因此结合真实 Agent 运行、规则检查与模型评分，评价回答、证据和工具行为。

## 1. 先分清项目里的两套评测

- **基础 Eval**：使用 `NoopLLM`（不生成模型结果的替代实现），检查少量样例中的分类、关键文件覆盖、规则兜底和输出结构。当前返回的 `tool_call_accuracy` 来自固定赋值 `1.0`，不能代表真实工具选择准确率。
- **ChatAgent RAGAS Eval**：运行生产版 ChatAgent 和已注册工具，收集实际回答、检索上下文、来源、工具调用与结束信息，再进行规则检查和评分。

基础检查适合发现部分实现问题，真实 Agent 评测才能进一步覆盖模型决策与工具配合。

源码：[基础评测](../backend/app/services/evals/runner.py#L37)、[固定就绪值](../backend/app/services/evals/runner.py#L143)、[真实 Agent 执行](../backend/app/services/evals/ragas_runner.py#L626)。

## 2. 一次真实评测怎样运行

```text
加载用例：问题、参考答案、预期来源和工具要求
    ↓
为每题创建独立评测会话，运行 ChatAgent
    ↓
收集预检索与工具检索证据、工具轨迹和最终回答
    ↓
硬规则检查 + Ragas 评分 → 保存逐题现场与汇总判定
```

每题复用项目资料、上下文组装与生产工具；参考答案用于评分，没有作为问题答案预先交给 Agent。运行结束后回滚评测保存点内的数据库写入，减少评测对业务会话的影响。

**硬规则**检查回答与检索上下文是否非空、是否命中预期来源、必需工具是否出现、是否存在工具错误，以及必需短语、禁止短语和正则表达式要求是否满足。

源码：[逐题执行与评分](../backend/app/services/evals/ragas_runner.py#L954)、[硬规则检查](../backend/app/services/evals/ragas_runner.py#L549)。

## 3. 模型评分具体看什么

Ragas 是检索与 Agent 评测库。项目使用 LLM Judge（模型评审器）等评分组件，计算以下核心指标：

| 指标 | 主要检查什么 |
| --- | --- |
| Context Precision | 检索到的证据是否相关 |
| Context Recall | 检索证据能否覆盖参考答案所需信息 |
| Faithfulness | 回答中的陈述是否得到检索上下文支持 |
| Answer Relevancy | 回答是否围绕用户问题 |
| Agent Goal Accuracy | 结合回答、工具调用与观察结果，是否完成目标 |

用例提供 `expected_tool_calls`（期望工具调用）时，还会计算工具调用准确率和 F1；它们会纳入本次门控。没有对应标注时，不能宣称已经测量了这两项工具指标。

源码：[指标评分输入](../backend/app/services/evals/ragas_runner.py#L283)。

## 4. 怎样判定通过、定位失败和做回归

当前整体通过要求：**所有用例硬规则通过、评分完整、各受门控指标的用例均分达到配置阈值**。均分达标并不要求每道题都达到该阈值，因此仍要查看逐题结果。

结果分别保存执行状态、质量状态和评分完整性。Judge 不可用、超时或评分缺失，需要与回答质量不达标区分；关闭 Judge 后也不能取得完整通过结论。

失败时可以展开逐题回答、证据、工具轨迹和诊断；异常评分可复用已保存现场重算，无需重新运行 Agent。回归比较会检查评测集 Hash（内容指纹）、Ragas 版本、Judge 模型和 Top-K 是否一致，并展示指标变化。这里的 Top-K 指检索数量上限。

源码：[均分与阈值](../backend/app/services/evals/ragas_runner.py#L685)、[整体判定](../backend/app/services/evals/ragas_runner.py#L842)、[异常重评分](../backend/app/services/evals/ragas_runner.py#L1114)、[回归比较](../backend/app/api/routes/evaluations.py#L365)。

## 5. 当前评测的边界

- 固定评测集加载与来源就绪检查已经实现，但当前工作区未找到默认目录中的固定集 JSON。自动从文档出题属于冒烟测试，不能作为独立的泛化或发布质量证据。
- 当前硬规则对预期来源检查的是“至少命中一个”，引用数仅作记录，也未直接把 Agent 的 `completion` 结束状态纳入硬门控，仍需人工审查覆盖范围。
- 模型评分存在误判；回归配置检查也未覆盖全部生产模型、提示词和数据快照。阈值通过只支持当前用例与配置下的结论。

源码：[固定集与冒烟测试](../backend/app/services/evals/suites.py#L95)。以上依据源码整理，本次未运行真实模型评测。

## 面试口述版

> 项目把 Agent 评测分成基础检查与真实运行评测。真实评测逐题运行生产 ChatAgent，保存回答、检索证据和工具轨迹，再结合硬规则与 Ragas 指标判断质量。整体通过要求规则全部满足、评分完整且指标均分达标；评分异常可以复用现场重试，修改后也能做配置受检的回归比较。当前还需要补齐固定评测材料与覆盖用例，不能用少量样例、固定就绪值或模型评分代替完整能力证明。
