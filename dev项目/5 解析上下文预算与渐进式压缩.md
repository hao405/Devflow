# 上下文预算与渐进式压缩（v1.0.1）

连续排查 CI 时，聊天与工具结果会越来越长。项目提前检查上下文压力，按预算裁剪模型输入，必要时把旧消息概括成摘要，同时保留近期原消息和回查线索。压缩改变的是当前上下文视图，旧聊天记录仍保存在数据库中。

## 1. 预算怎样分配

Token 是模型处理文本的计量单位。项目用字符规则粗略估算：中文汉字约一个 token，连续英文、数字约每四个字符一个；这些估计不能代替服务商的实际计量。

`ContextBudget` 为系统信息、记忆、检索证据、近期历史、工具观察和回答预留空间。默认比例分别涉及 12%、22%、34%、22%、10%，实际预算还受模型窗口、回答预留与配置下限影响。

| 字段 | 用途 |
| --- | --- |
| `reserved_response_tokens` | 为回答预留空间 |
| `system_tokens` | 当前仓库与会话信息 |
| `memory_tokens` | 压缩摘要、结构化记忆、上一轮摘要 |
| `evidence_tokens` | 检索到的相关证据 |
| `recent_tokens` | 最近用户与助手消息 |
| `tool_observation_tokens` | 本轮工具观察的预算 |

每次请求先组装摘要、会话记忆、最近封存摘要、相关证据与近期消息，再评估压力；不必等到窗口耗尽才裁剪。

源码：[预算计算](../backend/app/services/context_compression.py#L403)、[上下文组装](../backend/app/services/chat_memory.py#L469)。

## 2. 微压缩与循环内投影要分开说

`microcompact_messages()` 保留近期消息，对较旧、符合工具结果角色和工具名提示、且足够长的内容，生成来源说明与相关摘录。它是本地正文替换，不会编辑模型服务端的缓存。

当前组装器先筛选 user/assistant 消息，独立的 tool/tool_result 因而通常不能经这条历史路径进入微压缩。不能把这个函数的存在说成“所有旧工具轨迹都已被精准清理”，也不能清理助手最终回答来冒充工具压缩。

Agent 循环另外调用 `_runtime_tool_context()`，把状态中的观察转换成受限输入，称为投影。观察可能在此前已经被摘要，因此投影前记录也不总是工具完整原文。

源码：[微压缩筛选与替换](../backend/app/services/context_compression.py#L479)、[历史角色筛选](../backend/app/services/chat_memory.py#L493)、[循环内投影](../backend/app/services/agents/chat_agent.py#L1477)。

## 3. v1.0.1 怎样兼顾缓存

KV Cache 是服务端复用相同输入前缀计算的缓存。修改旧内容，会影响修改位置之后的复用；设置 `prompt_cache_key` 不会让不同正文自动变成相同前缀。

本版本固定单条工具观察的投影预算，避免每增加一条观察就重新截短旧条目，并将当前问题放在动态观察之前。超预算时按时间顺序批量省略旧观察，通常压到约 75% 预算留出余量；至少保留最新一条，必要时进一步缩短。状态字段记录省略位置，避免旧结果重新出现。

这仍是本地预算策略，没有接入服务端 `cache_edits`，批量清理仍可能损失部分缓存复用；它也不按工具调用 ID 定点删除。75% 是实现选择，尚未通过真实缓存成本实验验证最优性。

## 4. 正式压缩如何逐档增强

`ProgressiveContextManager` 同时评估原始有效历史和组装后的体量。默认压缩计划如下，消息关联保护可能让实际保留条数增加：

| 方案 | 近期原消息保留目标 | 摘要预算 |
| --- | --- | --- |
| 普通自动压缩 | 8 条 | 1800 token |
| 强压缩 | 4 条 | 1206 token |
| 最强方案 | 2 条 | 900 token |

摘要优先复用结构化会话记忆，否则请求模型；模型返回空摘要时使用规则提取，再有限补充路径、错误与待办等线索。直接抛出的异常会进入失败记录逻辑，多次失败有熔断处理。

压缩后新增 `compact_boundary` 记录，包含摘要、近期消息 ID、原文恢复引用和工作状态线索。后续上下文按边界读取；不会把原始聊天记录删除。模型决策仍将这些材料序列化进 `HumanMessage`，与 `SystemMessage` 一起调用模型。

源码：[分档计划](../backend/app/services/chat_memory.py#L833)、[摘要来源](../backend/app/services/chat_memory.py#L867)、[插入边界](../backend/app/services/chat_memory.py#L900)、[实际模型消息](../backend/app/services/agents/chat_agent.py#L444)。

## 面试口述版

> 项目结合预算裁剪、工具观察投影和分档摘要压缩控制上下文。v1.0.1 减少普通追加时对旧观察的改写，超预算再批量省略，并保留原有状态记录。正式压缩通过边界摘要与近期消息引用生效，精确原话仍需回查。当前没有服务端 cache_edits；本地测试证明预算和状态行为，真实命中率、延迟与任务质量还需独立评测。
