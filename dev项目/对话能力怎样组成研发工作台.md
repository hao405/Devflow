# 对话能力怎样组成研发工作台（核心精简版）

开发者判断一个 PR（代码合并请求）能否合并时，需要同时查看改动、CI（持续集成检查）、历史问题和项目约定。DevFlow-AI 将这些业务材料、对话上下文、分析能力与操作入口组织到工作台，让用户能够查看对象、提出问题、检查分析过程，再决定下一步。

## 1. 工作台由哪些部分组成

| 组成部分 | 用户能做什么 | 与对话的关系 |
| --- | --- | --- |
| 项目与会话 | 切换仓库、新建或继续会话 | 明确当前项目和对话历史范围 |
| 业务工作区 | 查看 Issue（问题单）、PR、CI，管理团队与项目知识，浏览技能和图谱 | 提供分析对象与项目材料 |
| 对话与分析入口 | 自然语言提问、点击对象分析、生成执行计划 | 调用后端检索、专项分析或工程工作流 |
| 结果与行动 | 查看答案、工具轨迹、上下文诊断和反馈，通过独立草稿页审阅操作 | 帮助核对结论、保留过程并推进操作 |

首页通过 `selectedRepo`、`selectedConversation` 等状态组织界面；切换项目后，重新加载对应的业务记录、会话和知识。业务工作区中的“技能&MCP”展示技能与工具服务状态，MCP 是连接工具服务的协议。

源码：[项目与业务数据加载](../frontend/app/page.tsx#L979)、[业务分区](../frontend/app/page.tsx#L575)。

## 2. 一句问题怎样进入项目上下文

例如用户选择仓库，输入“评估 PR #86 能否合并”：

```text
首页发送问题、repo_id 和 conversation_id
    ↓
后端读取当前仓库与会话，组装历史、记忆和检索证据
    ↓
ChatAgent 选择已注册工具，必要时调用跨领域工作流
    ↓
工具结果与答案返回页面，正常收尾时保存会话与轨迹
```

`ContextAssembler`（上下文组装器）从服务端取得近期消息、会话记忆和相关证据，并按预算组织。ChatAgent（对话 Agent）可以调用代码读取、知识检索、Issue/PR/CI 分析、报告和安全草稿等能力。

RAG（检索增强生成）负责查找可复用的非结构化知识；当前代码有工作区工具，业务状态有结构化查询。各类材料按用途进入处理链路，页面上可见的全部数据不会自动成为模型输入。

源码：[对话请求](../frontend/app/page.tsx#L2106)、[上下文组装](../backend/app/services/chat_memory.py#L463)、[注册的对话工具](../backend/app/api/routes/chat.py#L1297)。

## 3. 三类分析入口怎样配合

- **对话模式**：用户描述问题，`askAgent()` 调用 `/api/chat/stream`，由 ChatAgent 选择工具。跨领域问题可以调用工程工作流，组合多项分析。
- **对象分析按钮**：用户已经选定具体 Issue、PR 或 CI 时，按钮直接调用带对象 ID 的专项分析接口。例如 PR 分析走 `/api/pull-requests/{id}/analyze/stream`，不必先经过 ChatAgent 选工具。
- **计划模式**：先调用 `/api/chat/plan`，把任务、依赖和目标显示为计划卡；用户点击执行后，再把计划交给 `/api/chat/plan/execute/stream`。这一步确认的是分析计划，GitHub 写操作仍有独立的草稿确认流程。

三种入口围绕同一项目工作，但输入和上下文准备不同，不能假定得到的结果完全一致。

源码：[PR 对象分析](../frontend/app/page.tsx#L1207)、[生成计划](../frontend/app/page.tsx#L2220)、[执行计划](../frontend/app/page.tsx#L2288)。

## 4. 结果怎样支持下一步工作

对话通过 SSE（服务端事件推送）返回工具调用、结果和回答片段。首页展示执行轨迹与上下文诊断；正常结束后保存答案和事件，便于继续追问、查看历史，并对具体回答提交反馈。

需要写回 GitHub 时，对话可调用安全工具先保存可审阅草稿。实际写入由独立确认接口检查权限与草稿状态后执行，分析计划的执行按钮不能代替这项审批。

当前需要注意：

- `chatRequestContext()` 没有自动传入页面选中的业务对象；询问具体目标时应明确编号，或使用对应对象的分析按钮。
- Issue、PR、CI 分析主要依赖已同步记录，信息新鲜度取决于同步状态。
- 当前重点是检索、分析与受控操作，不能据此宣称已经具备自动修改源码、测试和发布的完整能力；权限身份也仍采用演示实现。

源码：[聊天携带的上下文](../frontend/app/page.tsx#L2076)、[回答反馈入口](../frontend/app/page.tsx#L2940)、[草稿确认执行](../backend/app/api/routes/action_drafts.py#L157)。

## 面试口述版

> 项目以仓库和会话确定工作范围，在业务工作区展示 Issue、PR、CI 和项目知识。用户可以自然语言提问，也可以直接分析具体对象，或先审阅任务计划再执行。后端组装上下文，通过 ChatAgent 工具和工程工作流完成分析，前端展示答案与执行轨迹，并保留历史和反馈。涉及外部写入时，再进入独立的安全草稿确认流程。当前仍需完善目标绑定、数据新鲜度和真实身份授权。

以上依据当前源码整理，未进行真实模型、GitHub 与部署环境的端到端验证。
